# C++ → TypeScript class map

**Historical after cutover.** This page records where every C++ class and struct of
`lekhcore/src` went in the TypeScript port (`lekhjs` and the React board in
`lekhboard-capacitor/lekh/src/board/`). It is written once for the port (Work
`01M4X7TCHFB862XGT68GPY071C`, spec 02 §19 and Appendix A) and is **not** kept current after
the C++ core is retired. The maintained page is
[/frontend/lekhjs/class-diagram.md](/frontend/lekhjs/class-diagram.md).

Verified 2026-10-17 against the lekhjs source: every name a row gives as a TS target exists in
`lekhjs/src` (or the board), except the rows marked _not built yet_ (the SVG/PDF exporter, the
export planner, remote-cursor painting), which later tasks of the Work build. Re-derive with
the checker below.

## How this page is checked

`lekhjs/parity/tools/class-map/cpp-to-ts-map.md` is a copy of this page as `prettier` formats it
(the same text, with padded tables), and `check-class-map.mjs` in the same folder reads it:

```
node parity/tools/class-map/check-class-map.mjs            # from lekhjs/; exit 1 on an AC-CLS-01 or -09 failure
node parity/tools/class-map/check-class-map.mjs --strict   # at cutover: any finding fails
```

- **AC-CLS-01/-14**: every `class`/`struct` declaration under
  `lekhcore/src/{lekh,base,math,geometry,fitter,recognizer,regularizer,akaar,bodh,license,resources}`
  (forward declarations, `enum class`, Lua and QuickJS excluded) has a row entry under its file
  (or its group row, such as `akaar/*`) with a code.
- **AC-CLS-02**: every P/M target written `<module>/<Name>` is an exported name of
  `lekhjs/src/<module>` (or of the board, for `board/…`). A free function is named in prose
  instead (it is not a class), so the check does not count it.
- **AC-CLS-09**: no exported TS class is the port of a dead (D) or dropped (X) class of §19.

When this page changes, refresh the copy from it (and the reverse); the two must not drift:

```
npx prettier --stdin-filepath parity/tools/class-map/cpp-to-ts-map.md < page.md > parity/tools/class-map/cpp-to-ts-map.md
```

The section numbers below are spec 02's, which the checker uses to find §19 and Appendix A.

## Differences from spec 02 (code wins)

The port followed the code where spec 02 and the other area specs named things differently.
This page records the names **as built**:

- `geometry::Rectangle` → `Rect`; `geometry::QuadBezierCurve` → `QuadBezier` (spec 01's names).
- `base::BaseUtil` (short ids) and `math::MathUtil` are **free functions** in `base`
  (`ids.ts`, `math.ts`), not the `ShortId` and `MathUtil` classes.
- The legacy object classes are **plain data** (the `LegacyObject` union in
  `io/legacy/legacy-converter.ts`), converted on read by the function `convertLegacy`; there is
  no `model/legacy/` folder and no `ObjectConverter` class.
- `semantic` is **free functions** (`project`, `compile`, `generate`, `lint`, placement) plus
  the `Compilation` class family of the delta compiler; there are no `SemanticProjector`,
  `SemanticDelta`, `SemanticGenerator`, `Lint`, `LintGrid` or `Projection` classes.
- The recognizer keeps spec 07's names: `Path` (not `StrokePath`), `RecShape` (not
  `CandidateShape`), `CanvasDelegate` (not `RecognitionScene`), `SnapshotCanvasDelegate` +
  `ObjectSceneStore` (not `SnapshotScene`), `MutationApplier`, `RecognitionClient`, `WorkerHost`.
  **Open owner question:** OQ-08 decided `StrokePath`, but the code kept `Path`. Either the code
  is renamed or OQ-08 is amended; until then this page uses `Path`.
- `IArrowObject` → `ArrowHeads`; `TransientDrawingObject` → `TransientStroke` (interaction);
  `MultiSelectedObjects` → the `MultiSelection` value plus `EditCommands` (edit);
  `SelectionWidget`, `SelectionLayout`, `InputFilter` and `OutsideClickHandler` are merged into
  `OverlayLayer`.
- Eight C++ structs were missing from spec 02 Appendix A and are added here: `PartInfo`
  (`lekh/ShapeRecognizer.cpp`), `Slot`, `Command`, `AutoPlaced`, `Field`, `NamedEnum`
  (`lekh/semantic/SemanticDelta.cpp`), `LineInfo` (`recognizer/ArrowRecognizer.cpp`) and
  `FuzzyComparable` (`bodh/FuzzyComparable.h`).

## Appendix A — Disposition of every C++ class and struct

Generated from the extraction (one row per source file; `akaar/`, `bodh/`, `recognizer/matching/` and `license/` grouped). Codes:

- **P** ported to the named TS class;
- **M** merged into it;
- **R** replaced (React, CSS, browser API, JS service);
- **X** dropped (obsolete or by decision);
- **D** dead code;
- **T** becomes a TS `type`/`interface` in the named module.

Files that declare no class or struct:

- `app/Const.h`: constants, to `interaction` and `session`;
- `update/Consts.h`: to the protocol constants of `sync` (consts.ts);
- `semantic/SemanticLint.h`: free functions, to `lint` in `semantic` (lint.ts);
- `MultiStrokeFramework.h`: dropped;
- `base/Identity.*`: dropped;
- `base/Const.h`: to `base`;
- `geometry/Polyline.*`: empty, dropped.
